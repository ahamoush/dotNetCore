شرح AuthorizationExtensions

تسجيل سياسات الصلاحيات من AppPermissions و RolePermissionMap

الغرض

يُستدعى من Program.cs عبر AddPermissionPolicies() لربط أسماء الصلاحيات بسياسات ASP.NET Core.

EnsureEveryPermissionHasARole ← FallbackPolicy ← سياسة لكل صلاحية

1) الكود الكامل

public static IServiceCollection AddPermissionPolicies(this IServiceCollection services)
{
    RolePermissionMap.EnsureEveryPermissionHasARole();

    services.AddAuthorization(options =>
    {
        options.FallbackPolicy = new AuthorizationPolicyBuilder()
            .RequireAuthenticatedUser()
            .Build();

        foreach (var permission in AppPermissions.All)
        {
            var roles = RolePermissionMap.RolesWith(permission);
            options.AddPolicy(permission, policy => policy.RequireRole((IEnumerable<string>)roles));
        }
    });

    return services;
}

2) EnsureEveryPermissionHasARole

إن وُجدت صلاحية في AppPermissions.All بلا أي دور في الخريطة، يرمي InvalidOperationException عند الإقلاع — حماية من سياسات ميتة.

3) FallbackPolicy

أي endpoint بلا [AllowAnonymous] يتطلب مستخدماً مصادقاً عليه حتى لو لم يُذكر [Authorize] على الـ Action.

السياسات المسمّاة (مثل Permissions.Projects.View) تستخدم RequireRole وليس claim الصلاحية مباشرة؛ الأدوار تأتي من JWT بعد المصادقة.
