شرح AuthController

مسارات المصادقة: تسجيل، دخول، وقراءة المستخدم من JWT

الغرض

AuthController يعرّض عمليات الهوية للعميل. المسار: [Route("api/[controller]")] أي api/Auth.

InputValidation ← IAuthService ← JSON

1) البنية والحقن

[ApiController]
[Route("api/[controller]")]
public class AuthController : ControllerBase
{
    private readonly IAuthService _auth;
    private readonly IValidator<RegisterDto> _registerValidator;
    private readonly IValidator<LoginDto> _loginValidator;
}

التحقق من المدخلات عبر FluentValidation قبل استدعاء IAuthService في Infrastructure.

2) نقاط النهاية

الطريقةالمسارالوصولما يُرجع
POSTapi/Auth/register[AllowAnonymous]200 بيانات التسجيل؛ 400 errors من Identity؛ 400 ValidationProblemDetails
POSTapi/Auth/login[AllowAnonymous]200 توكن وبيانات؛ 401 رسالة ثابتة؛ 400 تحقق
GETapi/Auth/me[Authorize]200 CurrentUserDto مع أدوار وصلاحيات من RolePermissionMap.ForRoles

3) Register و Login

IActionResult? invalid = await InputValidation.CheckAsync(_registerValidator, dto, ...);
if (invalid is not null) return invalid;
AuthResult result = await _auth.RegisterAsync(dto);
AllowAnonymous يتجاوز FallbackPolicy في Program.cs؛ باقي الـ API يتطلب JWT افتراضياً.

4) Me — قراءة Claims

Id = User.FindFirst("sub")?.Value ?? string.Empty;
Email = User.FindFirst("email")?.Value ?? string.Empty;
FullName = User.FindFirst(AppClaimTypes.Name)?.Value ?? string.Empty;

الأدوار من AppClaimTypes.Role؛ الصلاحيات المحسوبة وليست claims مباشرة في التوكن.
