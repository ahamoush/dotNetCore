شرح ملف Program.cs خطوة بخطوة

دليل للمبتدئ: ماذا تفعل الأسطر؟ وما معنى الكلمات والرموز المهمة؟

قبل أن نبدأ: ما وظيفة هذا الملف؟

هذا الملف هو نقطة تشغيل تطبيق ASP.NET Core Web API. يجهّز الخدمات التي يحتاجها التطبيق، ويضبط التحقق من هوية المستخدم باستخدام JWT، ويجهّز Swagger لتجربة الـ API، ثم يبني مسار استقبال الطلبات ويشغّل التطبيق.

قراءة الإعدادات ← تسجيل الخدمات ← إعداد JWT وSwagger ← بناء التطبيق ← Middleware ← تشغيل API

1) استيراد المكتبات باستخدام using

using System.IdentityModel.Tokens.Jwt;
using System.Text;
using Microsoft.AspNetCore.Authentication.JwtBearer;
using Microsoft.IdentityModel.Tokens;
using Microsoft.OpenApi;

// استيراد المكتبات المطلوبة
using ProjectManagementSystem.Api.Authorization;
using ProjectManagementSystem.Application;
using ProjectManagementSystem.Application.Authorization;
using ProjectManagementSystem.Infrastructure;
using ProjectManagementSystem.Infrastructure.Persistence;

كلمة using تخبر C# أنك تريد استخدام أنواع (Classes) موجودة داخل مساحة أسماء (Namespace)، حتى لا تضطر لكتابة اسمها الكامل في كل مرة.

المكتبةلماذا نحتاجها؟
System.IdentityModel.Tokens.Jwtللتعامل مع رموز JWT، ومنها إعداد JwtSecurityTokenHandler.
System.Textتوفّر أدوات النصوص، وهنا نستخدم Encoding.UTF8 لتحويل مفتاح نصي إلى بايتات.
Microsoft.AspNetCore.Authentication.JwtBearerتضيف آلية قراءة JWT المرسل في ترويسة Authorization والتحقق منه.
Microsoft.IdentityModel.Tokensتحتوي أنواع إعدادات التحقق من التوكن، مثل TokenValidationParameters وSymmetricSecurityKey.
Microsoft.OpenApiأنواع OpenAPI المستخدمة في تعريف أمان Swagger. قد يختلف الـ namespace المطلوب حسب إصدار حزم Swagger/OpenAPI.
ProjectManagementSystem.*هذه مساحات أسماء من مشروعك: طبقة API، وApplication، وInfrastructure، والتخزين، والتفويض.
في الملف المصدري يوجد التعليق العربي // استيراد المكتبات المطلوبة قبل أسطر مساحات أسماء المشروع.

2) إيقاف إعادة تسمية Claims تلقائياً

JwtSecurityTokenHandler.DefaultInboundClaimTypeMap.Clear();
JwtSecurityTokenHandler.DefaultOutboundClaimTypeMap.Clear();

JwtSecurityTokenHandler كلاس يتعامل مع JWT. وداخلَه خرائط تربط أسماء الـ Claims بأسماء أخرى.

  • DefaultInboundClaimTypeMap: خريطة التحويل عند قراءة التوكن الوارد.
  • DefaultOutboundClaimTypeMap: خريطة التحويل عند إنشاء/إخراج التوكن.
  • Clear(): تمسح عناصر الخريطة.

الهدف هو الحفاظ على أسماء الـ Claims كما هي، بدل تحويل بعض الأسماء تلقائياً إلى أسماء أخرى. وهذا مهم إذا كان تطبيقك يتوقع أسماء محددة مثل role أو أسماء معرفة في AppClaimTypes.

3) إنشاء Builder وتجهيز الخدمات

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();
builder.Services.AddApplication();
builder.Services.AddInfrastructure(builder.Configuration);

var تعني أن C# يستنتج نوع المتغير تلقائياً. وbuilder متغير يحمل أداة إعداد التطبيق.

  • WebApplication.CreateBuilder(args): ينشئ إعدادات بناء التطبيق، ويقرأ إعدادات التشغيل وسطر الأوامر وملفات الإعدادات مثل appsettings.json.
  • builder.Services: حاوية تسجيل الخدمات (Dependency Injection Container).
  • AddControllers(): يفعّل Controllers لاستقبال طلبات HTTP وتنفيذ Actions.
  • AddApplication() (في Application.DependencyInjection): AddValidatorsFromAssembly لكل FluentValidation في الطبقة، AddAutoMapper لملفات الـ Mapping، وتسجيل IProjectService وITaskService كـ Scoped.
  • AddInfrastructure(builder.Configuration) (في Infrastructure.DependencyInjection): ApplicationDbContext مع SQL Server وDefaultConnection، IdentityCore مع قواعد كلمة السر والأدوار، IProjectRepository وITaskRepository، IAuthService وIUserAdminService، وPermissionClaimsTransformation كـ IClaimsTransformation.
فكرة Dependency Injection: بدلاً من أن تنشئ كل Class اعتماداته بنفسه باستخدام new، تسجّل الخدمات هنا، ثم يوفّرها ASP.NET Core عند الحاجة.

4) قراءة مفتاح JWT من الإعدادات

var jwtKey = builder.Configuration["Jwt:Key"]
    ?? throw new InvalidOperationException("Jwt:Key is missing.");
  • builder.Configuration: مصدر إعدادات التطبيق.
  • ["Jwt:Key"]: يطلب قيمة المفتاح Key الموجودة داخل القسم Jwt في ملف الإعدادات.
  • ??: معامل null-coalescing؛ إذا كانت القيمة على اليسار null، ينفّذ ما على اليمين.
  • throw: يرمي استثناء ويوقف التنفيذ في هذا الموضع.
  • InvalidOperationException: نوع استثناء يشير إلى أن العملية لا يمكن تنفيذها بسبب حالة غير صحيحة، وهنا لأن المفتاح مفقود.

مثال توضيحي لشكل الإعدادات في appsettings.json (لا تضع مفتاحاً حقيقياً أو سرياً في مستودع عام):

{
  "Jwt": {
    "Key": "<مفتاح-JWT-سري-32+ حرف>",
    "Issuer": "YourIssuer",
    "Audience": "YourAudience"
  }
}
تنبيه أمني: لا تستخدم مفتاحاً قصيراً أو منشوراً على GitHub. في بيئة الإنتاج خزّنه في Secret Manager أو متغيرات البيئة أو مخزن أسرار مناسب، واستخدم مفتاحاً عشوائياً قوياً.

5) إعداد المصادقة Authentication باستخدام JWT

builder.Services
    .AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.MapInboundClaims = false;
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidateLifetime = true,
            ValidateIssuerSigningKey = true,
            ValidIssuer = builder.Configuration["Jwt:Issuer"],
            ValidAudience = builder.Configuration["Jwt:Audience"],
            IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(jwtKey)),
            RoleClaimType = AppClaimTypes.Role,
            NameClaimType = AppClaimTypes.Name
        };
    });

AddAuthentication(...) يضيف نظام المصادقة ويحدد المخطط الافتراضي. وJwtBearerDefaults.AuthenticationScheme يعني أن المخطط الافتراضي هو Bearer JWT.

AddJwtBearer(options => { ... }) يضيف معالج JWT Bearer. الرمز => يسمى Lambda Operator؛ اقرأه هنا بمعنى: «خذ options ونفّذ الإعدادات التالية».

شرح الخيارات

السطرالمعنى
MapInboundClaims = falseلا تحوّل أسماء Claims الواردة تلقائياً. يساعد على إبقاء الأسماء كما صدرت في التوكن.
ValidateIssuer = trueتحقق من الجهة التي أصدرت التوكن.
ValidateAudience = trueتحقق أن التوكن موجّه إلى هذا التطبيق/الجمهور.
ValidateLifetime = trueتحقق من صلاحية الوقت، مثل تاريخ الانتهاء exp.
ValidateIssuerSigningKey = trueتحقق من التوقيع باستخدام المفتاح المحدد.
ValidIssuerالقيمة المتوقعة للمُصدِر، مأخوذة من Jwt:Issuer.
ValidAudienceالقيمة المتوقعة للجمهور، مأخوذة من Jwt:Audience.
IssuerSigningKeyالمفتاح الذي سيُستخدم للتحقق من توقيع التوكن.
RoleClaimTypeاسم الـ Claim الذي يعتبره النظام دور المستخدم. هنا معرف في مشروعك باسم AppClaimTypes.Role.
NameClaimTypeاسم الـ Claim الذي يمثل اسم المستخدم. هنا AppClaimTypes.Name.

السطر التالي يحوّل المفتاح النصي إلى بايتات بترميز UTF-8، ثم ينشئ مفتاحاً متماثلاً:

new SymmetricSecurityKey(Encoding.UTF8.GetBytes(jwtKey))

«متماثل» يعني أن المفتاح السري نفسه يُستخدم عند توقيع التوكن وعند التحقق من توقيعه. لذلك يجب أن تتطابق إعدادات إنشاء التوكن والتحقق منه.

6) إضافة سياسات الصلاحيات

builder.Services.AddPermissionPolicies();

Extension في Api/Authorization/AuthorizationExtensions.cs: تستدعي RolePermissionMap.EnsureEveryPermissionHasARole() (تفشل الإقلاع إن وُجدت صلاحية بلا دور)، ثم FallbackPolicy يتطلب مستخدماً مصادقاً عليه، ثم لكل عنصر في AppPermissions.All تُنشأ سياسة بنفس الاسم وتستخدم RequireRole مع الأدوار من RolePermissionMap.RolesWith(permission).

الفرق المهم:

  • Authentication — المصادقة: من أنت؟ هل التوكن صحيح؟
  • Authorization — التفويض: بعد معرفة هويتك، هل مسموح لك تنفيذ هذه العملية؟

7) إعداد Swagger وواجهة OpenAPI

builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen(options =>
{
    options.AddSecurityDefinition("bearer", new OpenApiSecurityScheme
    {
        Type = SecuritySchemeType.Http,
        Scheme = "bearer",
        BearerFormat = "JWT",
        Description = "الصق التوكن فقط، من غير كلمة Bearer."
    });

    options.AddSecurityRequirement(document => new OpenApiSecurityRequirement
    {
        [new OpenApiSecuritySchemeReference("bearer", document)] = []
    });
});
  • AddEndpointsApiExplorer(): يضيف مستكشف معلومات نقاط النهاية ليستطيع Swagger جمع معلومات الـ API.
  • AddSwaggerGen(...): يسجّل مولّد مستند Swagger/OpenAPI.
  • AddSecurityDefinition("bearer", ...): يعرّف طريقة المصادقة التي ستظهر في Swagger باسم bearer.
  • Type = Http: نوع المصادقة هو HTTP Authentication.
  • Scheme = "bearer": نستخدم Bearer Token.
  • BearerFormat = "JWT": توضيح أن صيغة الرمز JWT.
  • Description: نص إرشادي يظهر للمستخدم في Swagger UI.
  • AddSecurityRequirement(...): يضيف متطلب الأمان إلى مستند OpenAPI، بحيث تعرف الواجهة أن العمليات تتطلب هذا المخطط.
  • new OpenApiSecuritySchemeReference("bearer", document): يشير إلى تعريف الأمان الذي اسمه bearer.
  • []: مجموعة فارغة في صياغة C# الحديثة، وتُستخدم هنا لقائمة نطاقات (scopes) فارغة.
بعد تشغيل المشروع وفتح Swagger UI، اضغط زر Authorize والصق قيمة التوكن. حسب الوصف الموجود في الكود، الصق التوكن نفسه دون كتابة كلمة Bearer؛ الواجهة تتولى تنسيق ترويسة المصادقة.
تنبيه توافق: واجهات OpenAPI تختلف بين إصدارات الحزم. إذا ظهر خطأ في Microsoft.OpenApi أو OpenApiSecuritySchemeReference أو صيغة AddSecurityRequirement، افحص إصدار Swashbuckle وMicrosoft.OpenApi المستخدمين، وطبّق الصيغة المطابقة لهما.

8) بناء التطبيق والتحقق من الـ Mappings

var app = builder.Build();
app.Services.AssertMappingsAreValid();
  • builder.Build(): ينهي مرحلة الإعداد ويبني كائن التطبيق القابل لتلقي الطلبات.
  • app.Services: يتيح الوصول إلى الخدمات المسجلة.
  • AssertMappingsAreValid(): Extension في Application.DependencyInjection يستدعي services.GetRequiredService<IConfigurationProvider>().AssertConfigurationIsValid() — فحص AutoMapper عند الإقلاع قبل استقبال الطلبات.

9) إنشاء Scope وتشغيل Seeder

using (var scope = app.Services.CreateScope())
{
    await IdentitySeeder.SeedAsync(scope.ServiceProvider, app.Configuration);
}
  • CreateScope(): ينشئ نطاق خدمات مؤقتاً. هذا مهم للخدمات ذات العمر Scoped مثل DbContext.
  • using (...): يضمن التخلص من النطاق وموارده عند الخروج من الكتلة، حتى لو حدث استثناء.
  • var scope: متغير يحمل النطاق المنشأ.
  • scope.ServiceProvider: مزوّد الخدمات الخاص بهذا النطاق، ومنه يحصل Seeder على الخدمات التي يحتاجها.
  • await: ينتظر انتهاء العملية غير المتزامنة دون حجز مسار التنفيذ بالطريقة المتزامنة التقليدية.
  • IdentitySeeder.SeedAsync(...) (في Infrastructure.Persistence): أولاً SeedRolesAsync ينشئ كل دور في AppRoles.All إن لم يوجد؛ ثم SeedSuperAdminAsync يقرأ Seed:SuperAdmin من الإعدادات ويتخطى إن غاب البريد أو كلمة السر، وإلا ينشئ المستخدم ويضمن دور SuperAdmin.
  • app.Configuration: يمرر إعدادات التطبيق إلى الدالة.

وجود الـ Seeder هنا يعني أنه يعمل عند بدء التطبيق. تأكد أن تشغيله المتكرر آمن ولا ينشئ بيانات مكررة.

10) إضافة Middleware لمعالجة الاستثناءات

app.UseMiddleware<ProjectManagementSystem.Api.Middleware.ExceptionHandlingMiddleware>();

الـ Middleware مكوّن يمر عليه طلب HTTP في طريقه إلى Controller، ويمكنه قراءة الطلب أو تعديل الاستجابة أو تمرير التحكم للمكوّن التالي.

في ExceptionHandlingMiddleware: يلتقط أي استثناء، يسجّله في ILogger، ويرد للعميل 500 مع JSON ثابت {"message":"An unexpected error occurred."} دون إرسال تفاصيل الاستثناء للعميل.

11) تفعيل Swagger في بيئة التطوير فقط

if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}
  • if: شرط؛ ينفذ ما بين الأقواس إذا تحقق الشرط.
  • app.Environment.IsDevelopment(): يتحقق هل التطبيق يعمل في بيئة Development.
  • UseSwagger(): يقدّم مستند OpenAPI بصيغة JSON.
  • UseSwaggerUI(): يقدّم واجهة الويب التفاعلية لتجربة الـ API.

بهذا الإعداد لا تظهر واجهة Swagger إلا في بيئة التطوير. قد تختار إعداداً مختلفاً للإنتاج وفق سياسة الأمان لديك.

12) ترتيب مسار الطلبات وتشغيل Controllers

app.UseHttpsRedirection();
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();
app.Run();
السطروظيفته
UseHttpsRedirection()يعيد توجيه طلبات HTTP إلى HTTPS عندما تكون إعدادات الاستضافة تدعم ذلك.
UseAuthentication()يفحص بيانات المصادقة، ويحاول تحديد المستخدم الحالي من التوكن.
UseAuthorization()يفحص هل المستخدم مسموح له الوصول إلى المورد أو تنفيذ العملية.
MapControllers()يربط مسارات Controllers بنظام التوجيه حتى يمكن الوصول إليها عبر HTTP.
Run()يشغّل التطبيق ويبدأ استقبال الطلبات، ويبقيه عاملاً حتى يتوقف.
الترتيب مهم: ضع UseAuthentication() قبل UseAuthorization()، لأن التفويض يحتاج إلى معرفة هوية المستخدم التي تنتجها المصادقة.

14) كيف تتخيل رحلة طلب محمي بـ JWT؟

  1. العميل يرسل طلباً إلى API ويضع التوكن في ترويسة HTTP: Authorization: Bearer <token>.
  2. UseAuthentication() يشغّل معالج JWT لقراءة التوكن والتحقق من التوقيع والمُصدر والجمهور ووقت الصلاحية.
  3. إذا كان التوكن صالحاً، تتوفر Claims المستخدم ضمن سياق الطلب.
  4. UseAuthorization() يفحص سياسة الوصول أو الدور المطلوب.
  5. إذا سمحت السياسة، يصل الطلب إلى Controller؛ وإلا يرجع التطبيق عادةً استجابة رفض مناسبة.

15) خلاصة تحفظها

  • using: استيراد مساحة أسماء.
  • builder.Services: تسجيل الخدمات التي سيستخدمها التطبيق.
  • JWT Authentication: التحقق من هوية صاحب التوكن.
  • Authorization Policies: تحديد ما يُسمح للمستخدم بفعله.
  • Swagger: توثيق وتجربة واجهات API.
  • Middleware: مراحل تمر بها طلبات HTTP.
  • Seeder: تهيئة بيانات أولية عند بدء التطبيق.
  • app.Run(): بدء تشغيل الخادم.
