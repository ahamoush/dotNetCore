شرح ملف ProjectManagementSystem.Domain.csproj خطوة بخطوة

دليل للمبتدئ: ما هي «بطاقة» مشروع .NET؟ ولماذا طبقة Domain هنا مكتبة بسيطة بلا HTTP ولا Entity Framework؟

قبل أن نبدأ: ما وظيفة هذا الملف؟

هذا ملف MSBuild بصيغة XML يخبر أداة dotnet كيف تبني مشروع ProjectManagementSystem.Domain. الناتج مكتبة (.dll) تحتوي نموذج المجال: الكيانات والتعدادات. الملف لا يشغّل خادماً ولا يفتح منافذ شبكة.

dotnet build ← قراءة csproj ← تجميع .cs ← إخراج Domain.dll

1) محتوى الملف كما في المستودع

<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>

</Project>

لا توجد عناصر PackageReference ولا ProjectReference في هذا الملف — أي لا حزم NuGet ولا اعتماد على مشاريع أخرى مذكورة هنا.

2) شرح العناصر

العنصرالمعنى
<Project Sdk="Microsoft.NET.Sdk">مشروع SDK قياسي لمكتبة C#؛ ليس قالب Web API.
TargetFramework net10.0الإطار المستهدف .NET 10 عند البناء.
ImplicitUsings enableالمترجم يضيف تلقائياً بعض توجيهات using الشائعة لملفات المشروع.
Nullable enableتفعيل تحليل القيم القابلة للإفراغ؛ يظهر تحذير عند احتمال استخدام مرجع null دون التعامل معه (مثل Project? في المهمة).
طبقة Domain في هذا الحل: تحتوي ملفات Entities وEnums فقط (حسب محتوى المجلد المصدري). لا يوجد في csproj إشارة إلى EF Core أو ASP.NET — فصل المنطق عن التخزين والويب يتم عبر مشاريع أخرى في الحل، وليس عبر هذا الملف.

3) ماذا يُبنى من هذا المشروع؟

  • BaseEntity.cs، Project.cs، ProjectTask.cs في مجلد Entities.
  • ProjectStatus.cs في مجلد Enums.

أي سلوك إضافي (قاعدة بيانات، واجهات API، مصادقة) يعيش في مشاريع أخرى تستورد هذه المكتبة؛ هذا الملف لا يصفها.

4) خلاصة تحفظها

  • مكتبة صنفية خفيفة: إعدادات بناء فقط + ملفات C# للمجال.
  • net10.0، ImplicitUsings، Nullable — الثلاثة مفعّلون.
  • لا تبعيات NuGet أو مشاريع مذكورة داخل csproj.
