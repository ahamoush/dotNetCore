شرح ملف IdentitySeeder.cs خطوة بخطوة

تهيئة الأدوار وحساب SuperAdmin الأول من الإعدادات عند بدء التطبيق.

قبل أن نبدأ: ما وظيفة هذا الملف؟

دوال ثابتة تُستدعى من الـ API (مثل Program.cs): SeedRolesAsync ثم SeedSuperAdminAsync.

AppRoles.All ← إنشاء أدوار ناقصة ← قراءة Seed:* ← مستخدم + دور

1) SeedRolesAsync — idempotent

foreach (var roleName in AppRoles.All)
{
    if (await roleManager.RoleExistsAsync(roleName))
        continue;
    var result = await roleManager.CreateAsync(new IdentityRole(roleName));
    // يرمي InvalidOperationException عند الفشل
}
متكرر بأمان: يتحقق من وجود الدور قبل الإنشاء — إعادة التشغيل لا تكرّر الأدوار.

2) SeedSuperAdminAsync — مفاتيح الإعدادات

مفتاح الإعداداتالدور في الكود
Seed:SuperAdmin:Emailالبريد واسم المستخدم؛ القيمة في ملف الإعدادات فقط
Seed:SuperAdmin:Passwordكلمة المرور عند الإنشاء؛ لا تُنسخ في التوثيق
Seed:SuperAdmin:FullNameاختياري؛ افتراضي النص «Super Admin» إن كان فارغاً
if (string.IsNullOrWhiteSpace(email) || string.IsNullOrWhiteSpace(password))
    return;

إن غاب البريد أو كلمة المرور يتخطى التهيئة دون خطأ.

var user = await users.FindByEmailAsync(email);
if (user is null) { /* CreateAsync */ }
if (!await users.IsInRoleAsync(user, AppRoles.SuperAdmin))
    await users.AddToRoleAsync(user, AppRoles.SuperAdmin);
متكرر بأمان: إن وُجد المستخدم يُكتفى بإضافة الدور إن لم يكن موجوداً؛ لا يُعاد إنشاء الحساب.
تنبيه أمني: احفظ Seed:SuperAdmin:Password في إعدادات آمنة (مثل User Secrets في التطوير) وليس في مستودع عام.

ملخص

يضمن وجود كل أدوار AppRoles وحساب مدير أعلى واحد قابل للتكوين — مع فحوصات وجود تمنع التكرار غير الضروري.
