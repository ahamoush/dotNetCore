أول ترحيل EF: إنشاء جداول Identity والمشاريع والمهام في SQL Server.

قبل أن نبدأ: ما وظيفة هذا الملف؟

صنف Migration جزئي اسمه InitialCreate. الطريقة Up تنشئ الجداول والفهارس؛ Down تحذفها بالترتيب العكسي.

مهم: الملف مُولَّد بواسطة Entity Framework Core عبر أمر مثل dotnet ef migrations add. لا تُعدِّله يدوياً إلا عند حاجة نادرة وواعية؛ غيّر النموذج في ApplicationDbContext وأنشئ ترحيلاً جديداً.

1) هيكل Up و Down

protected override void Up(MigrationBuilder migrationBuilder)
{
    migrationBuilder.CreateTable(name: "AspNetRoles", ...);
    // ...
}
protected override void Down(MigrationBuilder migrationBuilder)
{
    migrationBuilder.DropTable(name: "AspNetRoleClaims");
    // ... ثم AspNetUsers و Projects وغيرها
}

2) جداول التطبيق — أعمدة مهمة من Up()

الجدولأعمدة أو قيود بارزة
ProjectsId (Identity)، Name (100)، Description (500)، Status (افتراضي 1)، StartDate، DueDate، CreatedAt، UpdatedAt، IsDeleted (افتراضي false)، DeletedAt
TasksId (Identity)، Title (150)، Description (1000)، IsCompleted، DueDate، ProjectId → FK إلى Projects مع Cascade
AspNetUsersأعمدة Identity القياسية + FullName (100، مطلوب)
AspNetRolesId، Name، NormalizedName، ConcurrencyStamp
AspNetUserRolesمفتاح مركب UserId + RoleId، FKs مع Cascade
AspNetRoleClaims, AspNetUserClaims, AspNetUserLogins, AspNetUserTokensجداول Identity المعتادة مع FK إلى Users أو Roles

الاسمالجدولملاحظة

UserNameIndexAspNetUsersفريد على NormalizedUserName
