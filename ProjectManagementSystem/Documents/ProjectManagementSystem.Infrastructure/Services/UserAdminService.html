شرح ملف UserAdminService.cs خطوة بخطوة

عرض المستخدمين والأدوار، وتعديل أدوار مستخدم مع قواعد أمان لـ SuperAdmin.

قبل أن نبدأ: ما وظيفة هذا الملف؟

ينفّذ IUserAdminService باستخدام UserManager وApplicationDbContext لقراءة المستخدمين من جدول Identity وتحديث الأدوار داخل معاملة قاعدة بيانات.

1) GetUsersAsync

List<ApplicationUser> users = await _db.Users
    .AsNoTracking()
    .OrderBy(user => user.Email)
    .ToListAsync();

لكل مستخدم يُستدعى GetRolesAsync وتُرتَّب الأسماء أبجدياً في UserResponseDto.

2) GetRoles

return AppRoles.All
    .Select(role => new RoleResponseDto
    {
        Name = role,
        Permissions = RolePermissionMap.ForRole(role).ToList()
    })
    .ToList();

قائمة ثابتة من التطبيق: كل دور مع صلاحياته المتوقعة (لا تستعلم قاعدة البيانات).

3) SetRolesAsync — التحققات والتنفيذ

قاعدةالنتيجة
معرّف المستخدم فارغInvalid
المستخدم يغيّر أدواره بنفسهForbidden
لا أدوار بعد التنقيحInvalid
دور غير موجود في AppRoles.AllInvalid مع قائمة الأدوار المجهولة
المستخدم غير موجودNotFound
لمس SuperAdmin دون أن يكون الفاعل SuperAdminForbidden
إزالة آخر SuperAdminForbidden
لا تغيير فعلي (نفس الأدوار)Ok بدون معاملة
await using var transaction = await _db.Database.BeginTransactionAsync();
// RemoveFromRolesAsync / AddToRolesAsync
await transaction.CommitAsync();
تنبيه: عند فشل RemoveFromRolesAsync أو AddToRolesAsync تُعاد Invalid دون استدعاء CommitAsync — تعامل المعاملة مع await using عند التخلص من الكائن.

ملخص

خدمة إدارية تركز على الأدوار المعرفة في AppRoles وتحمي دور SuperAdmin من التعديل غير المصرّح به أو حذف آخر مسؤول.
