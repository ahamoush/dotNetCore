Engineering brief

العمارة

مشروع ويب واحد. المتحكم يعتمد الواجهة، والخدمة تعتمد السياق، والسياق يعتمد SQL Server. الاتجاه من الخارج إلى الداخل.

الطبقات

فاعل خارجي — عميل HTTP. لا مصادقة.
عرض — Controllers + Swagger في التطوير + ExceptionHandlingMiddleware
تطبيق — Interfaces ثم Services ثم DTOs. لا طبقة أوامر/استعلامات منفصلة.
نموذج — Models داخل نفس المشروع، وليس مشروعاً مستقلاً
بنية تحتية — Data/ApplicationDbContext.cs وMigrations
مخزن — SQL Server. لا طرف ثالث آخر.

اتجاه الاعتماد

Controller← IProjectService / ITaskService← ProjectService / TaskService← ApplicationDbContext← SQL Server

السهم يتبع اتجاه الاستدعاء: المتحكم يستدعي الواجهة، والتنفيذ المسجَّل في Program.cs هو الخدمة، والخدمة تفتح DbSet.

خط أنابيب HTTP

الترتيب في Program.cs بعد Build:

ExceptionHandlingMiddleware← Swagger إذا Development← HttpsRedirection← Authorization← MapControllers

استنتاج هذا ليس Clean Architecture متعدد المشاريع. الطبقات مجلدات داخل مشروع ويب واحد، والنموذج وEF والـ HTTP يُترجمون معاً.
