Engineering brief

نظرة عامة

نظام واحد يدير مشاريع ومهامها عبر REST، ويخزنها في SQL Server مع حذف ناعم للمشاريع وحذف فعلي للمهام.

المهمة

إنشاء المشاريع وتعديل اسمها ووصفها، والبحث فيها مع تصفية وترقيم، ثم إلحاق مهام بكل مشروع وتعليم المهمة مكتملة أو حذفها.

المكدس

الطبقةما هو موجود في المستودع
اللغة والإطارC#، ASP.NET Core، net10.0 في ProjectManagementSystem.csproj
واجهة المستخدملا صفحات. Swagger UI في بيئة التطوير فقط
البياناتEntity Framework Core مع موفر SQL Server
المصادقةغير مضافة. UseAuthorization موجود في Program.cs بدون AddAuthentication
الرسائل والطوابيرلا توجد
المهام الخلفيةلا توجد

خريطة المستودع

جذر مساحة العمل d:\DotNetBackend يحتوي مشروعاً واحداً: ProjectManagementSystem. لا ملف حل .sln في الجذر.

المسارالدور
ProjectManagementSystem/تطبيق الويب الوحيد
docs/app-explainer/هذا الشرح، وليس جزءاً من وقت التشغيل

طوبولوجيا التشغيل

عميل HTTP — لا تطبيق واجهة في هذا المستودع
عملية واحدة — dotnet run يستضيف Kestrel
SQL Server — عبر مفتاح ConnectionStrings:DefaultConnection

من يستخدمه

من الكود لا أدوار مستخدمين ولا صلاحيات. أي متصل بالمنفذ يستطيع استدعاء كل المسارات.
استنتاج الجمهور المقصود عميل HTTP خارجي (واجهة لاحقة أو Swagger أثناء التطوير)، لأن المتحكمات ترجع DTOs ولا ترجع كيانات EF.

حدود النظام

  • مشروع واحد يملك مهاماً كثيرة. المهمة لا تنتقل إلى مشروع آخر في UpdateTaskDto.
  • تعديل المشروع يغيّر الاسم والوصف فقط. الحالة وتاريخ البداية وتاريخ الاستحقاق مخزنة ولا تُحدَّث من واجهة التعديل.
  • حذف المشروع يضع IsDeleted وDeletedAt. حذف المهمة يستدعي Remove.
  • Exceptions/NotFoundException.cs ملف فارغ ولا يُستدعى من أي ملف آخر.

ما هو خارج النطاق

لا تسجيل دخول، لا مستخدمون، لا مرفقات، لا إشعارات، لا واجهة صفحات، ولا نشر أو Docker في المستودع.
